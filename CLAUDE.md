# wade

TUI file browser in Rust, in `src/wade-rs`. Runs on Windows Terminal, macOS and Unix/WSL terminals. There is no .NET code in the tree.

## Build & Test

```bash
cd src/wade-rs
cargo build
cargo test --locked
cargo run -- [path]
```

Validate Rust changes with:

- `cargo fmt` (config in `src/wade-rs/rustfmt.toml`; CI runs `cargo fmt --check` on the Linux job)
- `cargo clippy --all-targets --locked -- -D warnings` (CI runs it on Windows, Linux and macOS)
- `cargo clippy --all-targets --target x86_64-pc-windows-gnu` to compile `cfg(windows)` code (nothing runs)
- `cargo clippy --all-targets --target aarch64-apple-darwin` to compile `cfg(target_os = "macos")` code (nothing links or runs)

Don't run tests under Wine: CI's `rust (windows-latest)` job runs `cargo test --locked` on real Windows, so wait for the CI `rust` jobs after pushing.

## Golden tests

Suites under `src/wade-rs/tests/` compare against two fixture sets:

- Root `tests/golden/`: generated by the deleted C# implementation. **Frozen**: it can't be regenerated; don't edit by hand.
- `src/wade-rs/tests/golden/`: Rust-owned, regenerated with `WADE_UPDATE_GOLDENS=1`.

When an intentional behavior change breaks a frozen fixture, move it to Rust ownership, following the CSS pattern in `src/wade-rs/tests/highlight_golden.rs`.

## PTY tests

`src/wade-rs/tests/pty_smoke.rs` runs the built binary in a pseudo-terminal (`portable-pty`: a Unix PTY, or ConPTY on Windows), writes key bytes and reads the screen through `vt100`. It covers what the in-process App tests (`src/app/test_support.rs`) skip: terminal setup and restore, raw input decoding, resize, the main loop and exit. It runs in all three CI jobs. Notes:

- ConPTY asks for the cursor position (`ESC[6n`) at startup and holds all output until it is answered; the harness replies.
- Prefer checks that don't depend on the temp path: long paths get cut off in the status bar.
- Send Esc with `Session::escape()`, not `send(ESC)`: ESC followed by a key within 50ms is read as Alt+key.
- Text longer than a text box scrolls out of view; check it through a result instead (a rename's file name on disk).

## Key Conventions

- **No TUI frameworks**: rendering uses raw VT/ANSI escape sequences only (no crossterm, ratatui); output goes through a diffing `ScreenBuffer`.
- **Windows console input**: use Win32 `ReadConsoleInput`; do NOT enable `ENABLE_VIRTUAL_TERMINAL_INPUT`. VT processing is output-side only. Mouse uses `ENABLE_MOUSE_INPUT`.
- **Unix console input**: raw mode on `/dev/tty`. Arrow keys arrive as SS3 sequences (`ESC O A/B/C/D`) in alternate screen mode, not CSI. Mouse uses SGR mouse mode. `ESC` + a character is Alt+character; a lone ESC (or a sequence cut by a read) waits 50ms for the rest (`VtParser::has_pending`/`flush`).
- **Platform separator**: use the platform path separator, not hardcoded `/` or `\`.
- **Git status**: `git --no-optional-locks -c core.quotepath=false status --porcelain=v1` (`--no-optional-locks` is a global option and must precede the subcommand; it keeps background status from holding `index.lock`).
- **Avoid `Ctrl+Shift+<key>` keybindings**: Windows Terminal reserves many of them (`C`, `V`, `P`, `W`, `Tab`, etc.) and `Ctrl+Tab`, so they never reach the app.
- **macOS**: paths under `/var` and `/tmp` resolve to `/private/...` (FSEvents and `canonicalize` report the resolved form); volumes are case-insensitive by default. `osascript -l JavaScript` calls pass paths as `run(argv)` arguments; JXA `Ref()` out-parameters crash osascript (SIGSEGV), so pass `null` for `NSError**`/result pointers.
- **Windows**: deleting a directory symlink needs `remove_dir`, not `remove_file`; `symlink_metadata().is_dir()` is false for symlinks and junctions (use `std::fs::metadata` to follow links).
